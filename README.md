# بوت أكواد الكورسات - Deeb Learning

بوتين طريقة دفع:

1. **شام كاش** — تأكيد يدوي: المستخدم يبعت صورة إثبات التحويل، أنت (الأدمن) توافق يدوياً، البوت يبعت الكود.
2. **USDT شبكة TRC20** — تأكيد آلي بالكامل: المستخدم يحوّل ويبعت رقم العملية (TxID)، البوت يتحقق تلقائياً
   عبر API عام ومجاني من TronScan (بدون أي طرف ثالث غير رسمي، وبدون ما تحتاج تربط حسابك المالي بأي مكان)،
   ولو كل شي مطابق يبعت الكود فوراً بدون أي تدخل منك.

## الإعداد

### 1) توكن البوت وآيدي الأدمن (زي السابق)
- `BOT_TOKEN` من `@BotFather`
- `ADMIN_IDS` آيدي حسابك من `@userinfobot` (أو أرسل `/whoami` للبوت نفسه بعد ما يشتغل)

### 2) إعداد الكريبتو (اختياري - إذا بدك تفعّله)
- `TRON_WALLET_ADDRESS`: عنوان محفظتك على شبكة **TRC20** (تقدر تطلعه من أي محفظة/منصة بتدعم TRC20،
  مثلاً Binance أو Trust Wallet — تأكد إنه العنوان لشبكة TRC20 بالتحديد، مش شبكة تانية زي ERC20).
- `TRONSCAN_API_KEY`: اختياري، بس بيرفعلك حد عدد طلبات التحقق المسموحة بالدقيقة. تقدر تطلعه مجاناً
  من https://tronscan.org بعد ما تعمل حساب. إذا ما حطيته البوت رح يشتغل برضه بس بحد أدنى أبسط.

## لوحة تحكم عبر الويب (بدل SQL أو أوامر البوت)

بدل ما تدير الكورسات والأكواد عن طريق DB Browser أو أوامر تلغرام، صار في **صفحة ويب بسيطة**
تقدر منها:
- تضيف/تعدّل كورس (الاسم، السعر، رقم شام كاش، سعر الكريبتو)
- توقف/تفعّل كورس بزر واحد
- تلصق أكواد جديدة دفعة وحدة (كل كود بسطر) وتشوف شو مستخدم وشو متاح
- تشوف كل الطلبات (شام كاش وكريبتو) وحالتها

### كيف توصلها
- بمتغيرات البيئة ضيف: `ADMIN_WEB_USER` (اسم مستخدم من اختيارك) و `ADMIN_WEB_PASS` (كلمة سر قوية)
- على Railway: بما إنه المشروع صار فيه جزء "ويب" كمان، لازم تفعّل **Networking → Generate Domain**
  من إعدادات المشروع حتى ياخد رابط عام (زي `yourapp.up.railway.app`)
- افتح هاد الرابط بالمتصفح، رح يطلبلك اسم المستخدم وكلمة السر يلي حطيتهم

### ملاحظة تقنية مهمة
صار عندك ملف جديد اسمه `db.py` فيه كل منطق قاعدة البيانات، وبوتك (`bot.py`) ولوحة التحكم
(`admin_web.py`) الاثنين بيستخدموه، وبيشتغلوا مع بعض بنفس العملية عن طريق `main.py`.
**يعني الأمر يلي لازم تحطه بـ Start Command على Railway صار:**
```
python main.py
```
(مش `python bot.py` متل قبل)

## أوامر الأدمن (لسا موجودة، اختيارية إذا حبيت تستخدمها بدل لوحة الويب)

- `/addcourse الاسم;السعر;رقم_شام_كاش` — إضافة كورس جديد (السعر هون نصي، للعرض بس)
- `/setprice رقم_الكورس السعر_بالدولار` — **لازم** هاد الأمر حتى تفعّل خيار الكريبتو لكورس معيّن
  مثال: `/setprice 1 10` يعني كورس رقم 1 سعره 10 USDT بالكريبتو
- `/listcourses` — قائمة الكورسات + الأكواد المتبقية + سعر الكريبتو (إذا مفعّل)
- `/togglecourse رقم_الكورس` — تفعيل/إيقاف كورس
- `/addcodes رقم_الكورس` ثم كل كود بسطر — تعبئة مخزون الأكواد
- `/stats` — إحصائيات عامة (شامل عدد المدفوع بالكريبتو)
- `/whoami` — يعرض آيدي حسابك (مفيد لإضافة أدمن جديد)

## كيف تضيف أدمن ثاني

الأدمن مو شي بتضبطه من داخل البوت نفسه — هو بس متغير بيئة (`ADMIN_IDS`) بتعدله من لوحة تحكم
الاستضافة (Railway مثلاً). الخطوات:

1. اطلب من الشخص التاني يفتح محادثة مع `@userinfobot` (أو مع البوت تبعك ويبعتله `/whoami`)
   حتى ياخد آيدي حسابه (رقم).
2. روح للوحة تحكم Railway → مشروع البوت → قسم **Variables**.
3. عدّل قيمة `ADMIN_IDS` وضيف آيدي الشخص الجديد مفصول بفاصلة عن آيديك، مثال:
   ```
   ADMIN_IDS=111111111,222222222
   ```
4. احفظ — Railway رح يعيد تشغيل البوت تلقائياً بالمتغيرات الجديدة.
5. من هلق، الأدمن الجديد رح يوصله نفس إشعارات طلبات شام كاش (مع أزرار قبول/رفض)
   ونفس إشعارات تأكيد الكريبتو، وبيقدر يستخدم كل أوامر الأدمن (`/addcourse`, `/addcodes`, إلخ).

> ملاحظة: كل الأدمنية متساويين بالصلاحيات حالياً (ما في تمييز "أدمن رئيسي" عن "أدمن مساعد") —
> إذا بدك صلاحيات متفاوتة (مثلاً وحدة بس يشوف الطلبات بلا ما يقدر يضيف كورسات) احكيلي وبضيفها.

## طريقة عمل التحقق الآلي من الكريبتو (تفصيل تقني مبسّط)

1. المستخدم يختار الكورس → يختار "USDT (TRC20)" → البوت يعرضله عنوان محفظتك والمبلغ المطلوب
2. المستخدم يحوّل من محفظته الشخصية ويبعت رقم العملية (TxID) نص عادي بالشات
3. البوت يستدعي `https://apilist.tronscanapi.com/api/transaction-info?hash=...`
   (API عام من TronScan، ما بيحتاج تسجيل دخول أو ربط حساب)
4. يتأكد من: العنوان المستلم = محفظتك، العملة USDT، المبلغ >= السعر المطلوب، العملية غير مستخدمة قبل
5. لو كل شي تمام → يسحب كود من مخزون هاد الكورس ويبعته فوراً، ويسجل رقم العملية حتى ما ينستخدم مرتين

## أشياء منطقي تفكر فيها لاحقاً

- **تقلب سعر USDT**: USDT مرتبط بالدولار عملياً فمافي تقلب كبير، بس تأكد إنك بتحدّث `/setprice`
  إذا غيّرت سعر الكورس بالدولار.
- **الشبكة الصحيحة**: لو زبون غلط وحوّل عبر شبكة غير TRC20 (مثلاً ERC20)، العملية ما رح توصل
  لعنوانك أصلاً أو رح تروح لعنوان تاني بالخطأ - نبّه الزباين بوضوح بالتعليمات إنه TRC20 بس.
- **نسخ احتياطي**: خد نسخة عن `bot_data.db` بشكل دوري حتى ما تضيع الأكواد المستخدمة/المتبقية.
- **أمان التوكن والمحفظة**: التوكن وعنوان المحفظة بمتغيرات البيئة بس، لا تحطهم بكود عام على GitHub.
